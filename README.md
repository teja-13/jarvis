# JARVIS

JARVIS is a local-first desktop assistant for Ubuntu/GNOME. The repository is
organized as a small monorepo so each responsibility remains understandable:

- `backend/` — Spring Boot API and application rules.
- `frontend/` — Next.js command center.
- `desktop-agent/` — restricted local filesystem and application bridge.
- `ai-service/` — optional Python service boundary for document/AI features.

The first slice runs without a paid AI provider, microphone, or Docker. Memory
entries are kept in the backend process until PostgreSQL persistence is enabled.
Desktop actions are deliberately scoped to configured directories.

## Run locally

### Backend

```bash
cd backend
mvn spring-boot:run
```

The API listens on `http://localhost:8080`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

The command center listens on `http://localhost:3000`.

### Desktop agent

```bash
cd desktop-agent
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
JARVIS_ALLOWED_ROOTS="$HOME" uvicorn app.main:app --host 127.0.0.1 --port 8765
```

The agent is a localhost-only prototype. It does not expose a shell and does
not delete files.

Voice/text commands currently supported through the AI service include:

- `Open VS Code`, `launch Firefox`, `open terminal`
- `Find README files`
- `Open /home/teja/Documents/example.pdf`

These are translated into a small allow-listed desktop-agent action protocol.
Delete, move, rename, and other modifying file requests are blocked until a
preview and explicit confirmation workflow is implemented.

### AI service

The AI service uses the local Ollama instance by default:

```bash
cd ai-service
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
curl -X POST http://localhost:8000/interpret \
  -H 'Content-Type: application/json' \
  -d '{"text":"Explain what JARVIS can do"}'
```

Set `OLLAMA_MODEL` when using another locally installed model.

### Local PostgreSQL memory

The AI service uses the local PostgreSQL database configured in `.env`. On
startup it creates `jarvis_profile`, `chat_messages`, `chat_keywords`,
`memories`, `documents`, and `document_chunks`. Every chat request writes both
the user message and assistant response, and extracts searchable keywords for
each message. User-message embeddings are generated by Ollama's
`nomic-embed-text` model and stored locally in JSONB until the PostgreSQL
`vector` extension is installed.

## Configuration

Copy `.env.example` to `.env` and adjust values for the local machine. Never
commit credentials or provider keys.

## Development direction

The next milestones are PostgreSQL/Flyway persistence, real text conversation
orchestration, push-to-talk speech, and authenticated communication between the
backend and desktop agent. Risky file operations remain confirmation-gated.
